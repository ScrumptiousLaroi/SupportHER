# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

SupportHER is a SwiftUI iOS app that educates men about the menstrual cycle so they can support a partner, friend, sister or daughter. It is a Swift Playgrounds App project (`SupportHER.swiftpm`), not an `.xcodeproj`. It is fully offline: no networking, no third-party dependencies, all content is hardcoded in Swift.

## Build

All code lives in `SupportHER.swiftpm/`. Run commands from that directory.

```sh
# Build for simulator (the only CLI check available)
xcodebuild -scheme SupportHER -destination 'generic/platform=iOS Simulator' build CODE_SIGNING_ALLOWED=NO

# Open in Xcode to run / use previews
open SupportHER.swiftpm
```

- `swift build` does not work: `Package.swift` imports `AppleProductTypes`, which only Xcode / Swift Playgrounds provide.
- There is no test target and no linter.
- `Package.swift` is generated by Xcode ("do not edit by hand"). Change app settings (bundle id, orientations, deployment target) through Xcode's project UI.
- Target is iOS 26.0, Swift language mode 6 (strict concurrency). View models are plain `ObservableObject` classes; only `QuestManager` is annotated `@MainActor`.

## Architecture

The single `AppModule` target has `path: "."`, so every `.swift` file under `SupportHER.swiftpm/` is compiled regardless of folder. `MyApp.swift` and `ContentView.swift` sit at the package root; everything else is in `Sources/`.

`MyApp` configures global `UINavigationBar` / `UITabBar` appearance (opaque pink `#F2A1A1` nav bar, white titles) and defines the `Color(hex:)` initializer used everywhere. Navigation bar styling problems should be fixed there, not per view.

`ContentView` is a three-tab `TabView`, each tab wrapping its own `NavigationStack`:

| Tab | Root view | File | Contents |
|---|---|---|---|
| Dashboard | `mainDashboardView` | `ContentView.swift` | `CycleCalendarView`, `MoodCardView`, `PainCardView`, `CarePlanView` |
| Info | `View2` | `Sources/info.swift` | Phase slides, myths/facts, FAQs, embedded `DoctorAssessmentView` |
| Quest | `QuestHomeView` | `Sources/QuestHomeView.swift` | 7-day Support Quest, `QuestDayDetailView` sheet, `SupportScoreView` |

### Cycle state drives the dashboard

`CycleCalendarViewModel` (in `Sources/CycleCalendarView.swift`) is the one piece of shared state. `ContentView` owns it as a `@StateObject` and passes it to `CycleCalendarView` via `.environmentObject` and to the mood/pain cards as `@ObservedObject`. Everything on the dashboard is derived from the user-entered `cycleStartDate` / `periodEndDate`:

- Phase is computed with a fixed 28-day model (13 follicular, 1 ovulatory, 14 luteal); days inside the entered or projected period ranges are `.menstruating`.
- Mood card maps `currentPhase` to an emoji; pain card maps days-since-start to a level. Neither takes user input.
- `CarePlanView` only appears once `cycleStartDate` is set.

### Other features are self-contained

Each remaining feature owns its view model as a private `@StateObject` in its root view, with no cross-feature communication:

- **Care Plan**: `CarePlanViewModel` builds a checklist from `CarePlanPreferences`, which are collected in the `PreferencesSetupView` sheet.
- **Quest**: `QuestManager` holds the seven `QuestDay` entries (action, conversation starter, myth, fact) inline and tracks completed days.
- **Doctor assessment**: `DoctorAssessmentViewModel` maps Yes answers to a `RiskLevel` by severity tier, not a score: any single Yes must yield at least "Book a Doctor Visit". The rule, question tiers, test cases and medical sources are in `README.md`; keep that table in sync when changing questions. Nothing is persisted.

### Persistence

Everything is `UserDefaults`, with keys as string literals at the use site:

| Key | Owner |
|---|---|
| `cycleStartDate`, `periodEndDate` | `CycleCalendarViewModel` |
| `carePlanPreferences` (JSON) | `CarePlanViewModel` |
| `questCompletedDaysData` (JSON), `questStartDate` | `QuestManager` (`@AppStorage`) |
| `lastResetDate` | `CarePlanViewModel` and `ReadinessViewModel` (shared key) |

Care plan checklist tick state is in memory only; it is regenerated from preferences on launch.

### Things to know

- `ReadinessCheckView` / `ReadinessViewModel` are not referenced by any view. The care plan replaced them, but they still compile and share the `lastResetDate` key.
- `Assets.xcassets` holds `image1`–`image9`, used by the Info tab slides.
- The build currently emits deprecation warnings for `UIScreen.main` (`ContentView.swift`) and single-parameter `onChange(of:perform:)` (`CycleCalendarView.swift`).
- The latest commit notes one known bug: a navigation title that is not visible.
